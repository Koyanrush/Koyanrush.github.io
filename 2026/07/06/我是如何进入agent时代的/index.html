前言

这个标题其实具有一定误导性。你以为我要写我对AI认知发生改变或者技术迭代升级的完整过程，实则不然。因为这个过程快的惊人，回忆起来不会花费太多笔墨。我真正想写的是如何从0到1配置自己的可用agent。

从哪里开始呢？从那个冬天开始吧。

初识：人手一个的搜索工具

2025年年初，适逢新年。某只蓝色神秘小鲸鱼–DeepSeek，就在这时火了起来，额，至少是在那时被推送到我的手机上的。

说实话，在此之前我对整个AI的印象就局限于各种机器人，能握手开门躲避障碍那种就已经是我想象中的“高端产品”了。后来听说了ChatGPT，当我第一次得知人工智能这个东西还能单独拿出来当一个问答助手时，内心无疑是喜悦而激动的。

但是由于当时还不具备魔法手段，因此并未认为这东西能出现在我的日常生活中。现在国内终于也有类似应用了，毫不犹豫地，我打开应用商店下载了它。

我记得当时还处于一直被攻击的阶段，问问题不会百分百得到回复，更多的是一句“服务器繁忙，请稍后再试”。不过对于初次接触LLM的我来说，已经足够刷新我的认知了。

当时我的看法是：这玩意但凡能流畅使用，不得甩搜索引擎几条街啊。我相信当时肯定有很多人像我一样没少诟病国内的搜索引擎，想搜点东西，结果前几条全是广告，没一条有用的。想下个软件，能跳出来一列“官网”。试问屏幕前的你，有没有被这些山寨网站坑过？

DeepSeek的优势在，你问他什么就是什么，不会出现什么垃圾信息。最棒的一点是它的个性化，正如世界上不存在两片一样的树叶，世界上也不会有两个人永远问出一模一样的问题。很多时候面对毫无前人经验可言的报错，我们会感到强烈的迷茫与无助，而大语言模型的出现解决了这个困境。你可以向它们描述那些独属于你自己的问题，描述得越详细，回答就越准确。

彼时作为一位高中生的我也是自然而然的产生了用AI来解题的想法。在牢D还没推出识图功能和语音输入的时代，我只能一个个字符地手敲题目，发现虽然效率低，但是不仅做对了，还附带解题思路。那时已经有人研究出了“角色扮演”的玩法，比如用“百岁好学太奶不想被时代淘汰”设定背景，这样就能获得保姆级题目攻略。

这下好了，不止百度，作业帮也要失业了。毕竟全免费的东西，没理由不去用吧？

进阶：睁眼看世界

2025年下半年是我技术爆炸的一个重要节点，倒不如说，大学前我对电脑几乎没什么游戏之外的了解。

其中最重要的一进步就是掌握了“魔法”的使用，开了第一个也是唯一一个谷歌账号。由是解锁了Gemini、ChatGPT和Claude，真正用上了国际先进模型。也就是这时我意识到国内外的差距所在，不是我崇洋媚外，主要人家的东西确实更好用啊。

举个例子，那时我开始尝试用ai解决CTF题目，国内模型如DeepSeek、千问等普遍有个问题，说好听点叫无中生有，难听点就是太会胡编乱造了。
一旦题目复杂度上升，它自己做不出来不会告诉你，反而会虚构一个flag出来应付你。(国内主流模型中，我唯一从未使用过的是豆包。一开始只是单纯觉得图标唐😛，后来听说能力也不行，不光擅长虚构还是讨好型人格，这下更坚定了我远离它的信念。)

所以我还在用的国产模型只剩下了有初遇buff加成的DeepSeek，而且仅限于一些日常问题和纯中文的报告撰写之类的。原因是我觉得本土诞生的模型用中文回答更自然。涉及到解题尤其是编程与开发，那就没有国产模型的份了。

至此，手握顶级模型的我解决起问题可谓是得心应手了…..吗？

突破：跳出对话框外

时间来到2026年。这一年火了一个更新奇的东西–openclaw，也就是我们俗称的“龙虾”。这东西为啥能掀起这么大风浪？

不是，什么叫AI能操控你的电脑了？而且权限比你还高？

对，就是这么逆天。由于权限高的吓人，在全网爆火后的下场是被各大高校紧急封杀，国家也下场发布了相关预警与规范指引。

先别急着喷这种“一刀切”行为，因为这东西是真有可能对你的磁盘执行“光盘行动”。

在我看来这东西的魅力在于，以往我们的AI助手被局限在了对话框中：你遇到问题，比如安装某款工具时遇到了报错，你会先复制错误信息给AI，AI读过以后给出自己的建议或者猜测（一般都不止一条），你再根据AI给出的这些内容返回进行调试。如果没有解决或者遇到全新报错就重复这个过程。很麻烦不是吗？

现在好了，openclaw直接给AI模型赋予了“动手能力”。AI是大脑，openclaw就是AI开的高达，两者一起天下无敌。你只需要在任意位置启动它，告知问题发生的路径，它就能“进入”那里，全自动解决问题。你唯二需要的操作是写提示词和审批进程。

对能否驾驭这样强大的工具我是没底的，所以当我想亲手试试这种全自动帮手的时候，我选择寻找它的同类试试水温。于是我拥有了opencode、codex和claude code。它们共同构成了我现有的agent体系。

agent，英文原意为代理人，在这个ai时代，它诞生了名为“智能体”的全新含义。我提到的这三种，以及龙虾在内都是agent的一种。他们本身没有思考能力，只有搭配LLM才能发挥作用。

那么该如何愉快地使用它们呢?

👈何为中转站？

API 中转站是一个位于用户和真正模型服务商之间的中间服务器，它接收你的 API 请求，再转发给目标模型服务，并把结果返回给你。

使用api中转站对我们有以下几个好处

统一接口：最直观的作用是能让你“一key解千愁”，从中转站创建一个key，能接入不同接口的agent，调用不同的模型。

隐藏 API Key：保护你的账号密钥，防止直接暴露在开发环境中。

降低延迟：在国内经久不衰的一个问题，中转站使用国内节点，能够优化响应速度。

协议转换：将一种 API 格式转换成另一种 API 格式，让不同生态兼容。这就是能实现codex接入deepseek的原因。

只是拥有了agent+LLM，在Agent时代只是基础中的的基础。想晋升为agent高手，你还得玩的明白一些前沿工具。它们大体分为两类，一类封装为Plugins，另一类封装成MCP Server。

Plugins

直译为插件，能够增加agent本身具有的能力。本质上是将特定领域的多种能力打包在一起的模块化组件。可以理解为涵盖了下面几个概念，也就是说，一个功能齐全的plugins是包括Tools、Commands、Skills这些东西的。与MCP的最大区别是Plugin是“定制的”，而MCP是“通用的”。

plugins下封装：

Tools

本地原生工具，具体表现形式为直接写在Agent项目代码里的函数。例如，在Python脚本中，你写了一个def get_weather(city)，然后打上 @tool标签。这种本地Tool与你的Agent在同一个进程/内存空间中运行。适用于Agent内部的小型、高频、轻量级任务。

Commands

直译为“命令”，你应该能看出这个名字里含有的强制意味。没错，这玩意跟Tool的区别就是Commands是强控制性的系统指令，而Tool是大模型（LLM）主动决定要不要调用的。

Skills

这个最有意思，它有点像“角色设定”。目的是给一些相似的工作总结出一个标准的应对方式。一般情况下是硬编码在Agent框架里的文本字符串或本地.txt / .json或者.md文件。就像你公司里新招来的实习生，你肯定不愿意每次都告诉他“遇到xx问题时你要xx做”，而应该直接给他一本《员工守则》，让他需要时自行查阅。从这个概念出发，热爱创作的大家也搞出了一些有趣，甚至是抽象的Skill。

MCP

让AI连接外部工具和数据源的标准协议，就是给agent使用过程中调用外部工具设计了一套统一的规则。MCP Server是实现了MCP协议的具体程序。与Plugin是平级的，互不隶属。共同点在于都像一个“集装箱”，打包了些别的东西。区别在于Plugin通常是你自己写在代码里的本地模块；而MCP Server是遵循标准化协议的独立服务（比如你可以把一个MCP Server分别接入给Claude和Codex用）。

MCP家族包括：

MCP Tools

与Plugins中的Tool不同，这是运行在独立的MCP Server上的函数。Agent只是通过MCP协议发送一段JSON请求,MCP Server收到后执行，再把结果返回给Agent。优势在于可以跨语言，用Python写的agent可以调用Rust语言的MCP Server中的Tool。还有安全性，MCP Server处在一个隔离的环境中，运行时不会攻击到agent本身。

MCP Resources

标准化的只读数据源。相当于Agent的“外接眼睛”。比如你想让Agent读取本地复杂的数据库，如果写Tool会非常麻烦。通过MCP Resource，你可以定义一套类似 postgres://company_db/users 的标准路径。Agent可以直接通过协议把这些海量数据作为上下文读取进来，而无需关心底层的数据库是怎么连的。

MCP Skills

Skills的MCP版本，现在是存放在MCP Server中的动态模板了。优势也是MCP系列的“通用优势”：你可以把公司所有优秀的Prompts统一打包在一个MCP Server里。无论员工是用Claude桌面端，还是内部自研的Agent，只要连上这个 Server，就能直接调用同一套标准话术。

获取并使用

下面提供几种方案来获取这些工具，建议拥有Github账户再浏览这一部分，没有的话请直接移步实操环节。

一、 通过官方开源库或者平台内置市场。

最权威最安全的途径。比如Anthropic（Claude的开发公司）官方在GitHub上维护了一个名为servers的核心仓库，这里面有官方写好的、质量极高的一手MCP，比如Google Drive、Slack、PostgreSQL数据库等。此外，像Dify、Coze、OpenAI这样的平台通常在UI界面里就内置了“插件/工具商店”，通常会有一些框架专属的插件。你需要什么能力（比如“联网搜索”、“生成图片”），直接在界面上点击“添加”并填入必要的 API Key 即可。

引用站外地址
servers库
https://github.com/modelcontextprotocol/servers

二、 通过第三方目录站点或者包管理器。

你可以去访问一些专门的MCP索引网站，比如Smithery或者MCP Directory，像逛应用商店一样在上面搜索你需要的工具。

Smithery是全球最大的MCP服务器注册表，收录超过3000个MCP Server，支持一键复制安装命令，适合快速集成到开发环境。

引用站外地址
Smithery
https://smithery.ai/

MCP Directory，目前最全面的开源 MCP 服务器和技能目录，支持一键安装到各类 AI 客户端。

引用站外地址
MCP Directory
https://mcp.directory/

还可以使用代码框架生态包（如 LangChain、Semantic Kernel）：如果你是用代码写Agent，你需要去包管理器（如npm）获取Tool。比如在 LangChain中，你可以直接pip install langchain-community，里面包含了成百上千个开发者贡献的本地Tools。

MCP的获取与运行通常不是下载一个软件安装包，而是在你的agent的配置文件中添加一行启动命令。常见的运行方式是通过Node.js (npx)、Python工具(uvx 或 pip)，甚至是Docker容器直接拉取并运行。

风险&免责声明

看到这里，你应该已经开始使用网络代理和中转站服务了。

首先你需要知道使用中转站和网络代理不是一个被鼓励的行为，其中使用网络代理（魔法）访问外网更是一种违法行为。你只要使用，就要承担一定的风险。不过话又说回来，跟你看小电影类似，只要不去搞什么交易啊，反动言论啊，肆意传播啊，满足一下个人需求，帽子叔叔不会找你喝茶的。

以上是一方面的风险。另一方面，由于agent权限大，你懂的又不多，所以建议只在特定目录内启动并使用agent。不要让agent在你的系统盘里私搭乱建，除非你真的知道Agent在做什么，毕竟这玩意是真的有可能把你的整个磁盘推掉。多去网上搜索搜索相关案例，你就会具备应有的警惕。
